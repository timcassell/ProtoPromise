# Change Log

## v3.6.0 - TBD

Enhancements:

- Added `Proto.Diagnostics.CausalityTrace` (see [Causality Traces](../Guides/causality-traces.md)).
	- Works in DEBUG and RELEASE mode (`CausalityTrace.IsEnabled`).
	- Follows causality through async functions, continuations, `SynchronizationContext` and thread pool hops, `Promise.Run`, timers, cancelation callbacks, `Progress` reports, `AsyncLazy<T>`, `ParallelAsync` loops, async synchronization primitives, and channels.
	- Use `CausalityTrace.Capture` and `CausalityTrace.EnterScope` to trace your own async operations.
	- `CausalityTrace.MaxDepth` and `CausalityTrace.MaxOuterTraces` limit how much of each trace is kept.
	- `Promise.Config.AwaitTracesEnabled` setting also traces where `async Promise` functions await, so that their traces include what continued them before each await, whatever they awaited (including custom awaitables).
	- Objects are not pooled while causality traces are enabled.
- Added `UnhandledException.CausalityTrace`.
- `UnhandledException` is no longer abstract, and its constructor is public.

Fixes:

- Fixed `Timer.DisposeAsync()` never completing after a callback of a timer from `TimerFactory.System` or `TimerFactory.FromTimeProvider` threw an exception.
- Fixed a configured await that threw `InvalidOperationException` (invalid await) didn't restore the `async Promise` function's continuation context.

Optimizations:

- Removed `Promise.Config`'s static constructor.

Deprecated:

- Deprecated `Promise.Config.DebugCausalityTracer` and `Promise.TraceLevel`. (Prefer `Proto.Diagnostics.CausalityTrace.IsEnabled`, which also applies in RELEASE mode.)

Misc:

- Causality traces are no longer captured by default in DEBUG mode (previously, `Deferred.Reject` was traced). Set `CausalityTrace.IsEnabled = true` to capture them.
- Changed `UnhandledException.Message` to say how to get a causality trace when it has none.
- For a rejection with a value that is not an `Exception`, `UnhandledException.InnerException` is now `null` (it was an internal exception with the same message, whose stack trace was where the value was rejected in DEBUG mode; use `UnhandledException.CausalityTrace` instead), and its message says `value:` instead of `Value:`.
- An exception thrown by `Promise.Config.UncaughtRejectionHandler` is now caught and rethrown in the `ForegroundContext` or `BackgroundContext` (or the thread pool if neither is set), instead of escaping into the code that completed the promise.
- Added net9.0 build target.
